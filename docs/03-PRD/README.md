# Product requirements

> Project: PDF Editor Extension | Version: 0.1 | Status: Draft | Updated: 2026-11-01 (Asia/Calcutta) | Owner: Project owner | Phase: P0 planning; P1 feasibility next

## Scope and ownership
Confirmed product vision is broad PDF editing in the source language, private distribution, on-device processing and future subscription support. Phase ordering is a proposed engineering plan; no universal fidelity guarantee. The project owner owns product decisions; engineering must report measured support. [BRD](../02-BRD/README.md) owns business rules.

## Acceptance definitions

### REQ-001 / AC-001: Import and classify
Given a local user in the relevant phase, User selects a local PDF; validate content and size, inspect each page and region, show native/scanned/mixed/unsupported status. Password prompt when required; malformed, over-limit and wrong-password inputs fail without replacing current work.

Pass condition: Both supplied samples classify correctly; rejected imports leave prior edits intact. Verify with TEST-001; failure must preserve prior valid state and offer retry, adjustment or cancellation.

### REQ-002 / AC-002: Replace existing text
Given a local user in the relevant phase, User selects a supported text run and changes letters/words/lines. Preview before commit; remove replaced source content rather than cover it. Preserve unchanged page content.

Pass condition: Changed-region extraction contains replacement and no removed original; no duplicate hidden text; unrelated text and graphics unchanged. Verify with TEST-002; failure must preserve prior valid state and offer retry, adjustment or cancellation.

### REQ-003 / AC-003: Preserve formatting and language
Given a local user in the relevant phase, Resolve font, glyphs, point size, color, baseline, spacing, direction and transformations. Keep Unicode input; perform script shaping. Show missing-glyph/font/overflow choices; never silently translate or substitute.

Pass condition: Exact mode retains source style and geometry; missing glyph blocks exact mode; approximate choice is labeled; longer text cannot clip silently. Verify with TEST-003; failure must preserve prior valid state and offer retry, adjustment or cancellation.

### REQ-004 / AC-004: Edit scans with local OCR
Given a local user in the relevant phase, Rasterize selected scan region, choose supported recognition language locally, review OCR text and edit image content with visible approximation. Mixed pages use per-region paths.

Pass condition: OCR runs without sending document data; user corrects recognition; scan export changes actual pixels rather than only invisible OCR text; background mismatch is disclosed. Verify with TEST-004; failure must preserve prior valid state and offer retry, adjustment or cancellation.

### REQ-005 / AC-005: History and session safety
Given a local user in the relevant phase, Undo/redo committed edits; cancel preview without mutation. Close/switch warns on unsaved work. Session data defaults to memory; optional local recovery deferred until separately implemented.

Pass condition: Undo/redo restores expected revisions; import/export cancel preserves document; crash recovery is not promised for memory-only sessions. Verify with TEST-005; failure must preserve prior valid state and offer retry, adjustment or cancellation.

### REQ-006 / AC-006: Export and verify
Given a local user in the relevant phase, Save a new PDF copy using a revision snapshot; reopen/parse generated bytes before download. Preserve supported links/forms and page structure. Warn for signature invalidation; unsupported preservation blocks export or requires explicit documented conversion.

Pass condition: Source hash unchanged; output opens in independent reader; page count/dimensions retained unless explicit page edit; failed export retains edits and exposes retry. Verify with TEST-006; failure must preserve prior valid state and offer retry, adjustment or cancellation.

### REQ-007 / AC-007: On-device privacy
Given a local user in the relevant phase, Process PDF bytes, text, fonts extracted from documents, images and OCR locally; no document-derived telemetry or cloud fallback. Separate optional future account traffic.

Pass condition: Network capture shows zero document-related outbound payloads during import, render, edit, OCR and export, including failures. Verify with TEST-007; failure must preserve prior valid state and offer retry, adjustment or cancellation.

### REQ-008 / AC-008: Other content and PDF variants
Given a local user in the relevant phase, Select supported images to move/resize/replace/delete; scoped vector editing after engine validation. Detect forms, encrypted/signed PDFs, rotated text, outlined text and attachments; capability-gate unsupported operations.

Pass condition: Each advertised operation has a tested fixture; unsupported content stays intact or blocks export; no password bypass or accidental form flattening. Verify with TEST-008; failure must preserve prior valid state and offer retry, adjustment or cancellation.

### REQ-009 / AC-009: Chrome Store distribution
Given a local user in the relevant phase, Package MV3 extension with bundled executable assets, minimal permissions, disclosures, license notices and reproducible artifact.

Pass condition: Clean-profile install and edit/export work; package audit passes; store submission and approval are separate recorded states. Verify with TEST-009; failure must preserve prior valid state and offer retry, adjustment or cancellation.

### REQ-010 / AC-010: Future subscriptions
Given a local user in the relevant phase, Add account-linked entitlements without document upload; checkout/cancel/renew/failure flow via provider and server verification.

Pass condition: Duplicate/out-of-order events do not duplicate entitlement changes; cross-user access denied; sign-out purges account cache but not current local edits. Verify with TEST-010; failure must preserve prior valid state and offer retry, adjustment or cancellation.

### REQ-011 / AC-011: Accessible and responsive editor
Given a local user in the relevant phase, Keyboard-select text through an accessible text list, use labeled controls, visible focus, zoom and readable status announcements.

Pass condition: Core import/edit/export works without pointer; 200% UI zoom does not hide actions; OCR and worker tasks cancellable without losing edits. Verify with TEST-011; failure must preserve prior valid state and offer retry, adjustment or cancellation.

## Proposed limits and quality budgets
Initial safety caps proposed for P1: 50 MiB input, 200 pages, maximum 25 million decoded pixels per OCR task, one OCR task at a time. Validate before allocation and permit controlled cancellation; these are configurable safety ceilings, not measured supported maxima. Q-005 must set published limits based on benchmarks.

Targets, not measured results: progress acknowledgment within 500 ms; no synchronous whole-document parsing on UI thread; cancellation acknowledgment within 2 seconds by worker termination if necessary. Benchmark on recorded OS/Chrome/CPU/RAM with 1/10/100-page synthetic PDFs. Rendering tolerance and retention checks are in the domain module and tests.

Document language differs from app UI language. English UI initially is an assumption; source text must not be translated. P1 probes English, Hindi/Devanagari, Arabic RTL and CJK. No language is publicly declared editable until fixtures pass. Embedded signatures and protected documents require special handling; editing does not preserve digital signature validity.

## Flow recovery
Import pending -> cancel returns to current document. Edit preview invalid -> preserve draft and explain glyph/overflow problem. Worker crash -> keep original plus committed operation log in UI memory, recreate worker and replay validated operations; warn if recovery fails. Export uses frozen revision; either disable mutations while exporting or clearly export the chosen snapshot. Never mark edits saved before file download is initiated successfully; the browser cannot prove the user retained the downloaded file.
